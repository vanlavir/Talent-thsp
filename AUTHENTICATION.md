# Регистрация и авторизация, версия 0.2

В приложении нет зависимости от личности ChatGPT: сервер принимает собственную сессию, а заголовки oai-authenticated-user-* не дают доступа.

## Данные

В SQLite/D1 созданы users, sessions и auth_limits. Локальная база хранится в .wrangler/state/v3/d1/*.sqlite; опубликованная версия использует D1 на базе SQLite. ORM-схема: db/schema.ts. Изменение схемы: drizzle/0001_small_mordo.sql. Уже применённые миграции не менять и не повторять.

Пользователи: уникальный нормализованный логин, уникальная почта, bcrypt-хеш (cost 12, индивидуальная соль), неизменяемая роль и время создания. Пароль не хранится открытым и не возвращается API. Ввод ограничен 72 байтами UTF-8, чтобы bcrypt не обрезал пароль незаметно.

Сессия: случайный токен 256 бит, SHA-256 хеш токена в базе, привязка к пользователю и срок 7 дней. В браузере используется HttpOnly cookie с SameSite=Lax, Secure на HTTPS. Выход удаляет сессию из базы, а не только cookie. Истёкшие сессии не принимаются.

## Маршруты

- GET /api/auth: текущая учётная запись или user:null.
- POST /api/auth: action register / login / logout.
- POST требует точного совпадения Origin с адресом сайта.
- Вход и регистрация ограничены по IP и нормализованному логину; счётчики сохраняются в базе. Неверный пароль и отсутствующий логин дают одинаковое сообщение.
- Логин — латинские буквы, цифры и _, 3–32 символа. Новый пароль — от 12 символов, до 72 байт UTF-8.
- API кабинета берёт роль из users; прежнее действие смены роли запрещено.

Полная спецификация: public/openapi.json.

## Проверка

`python scripts/check-auth.py` при работающем локальном dev-сервере. Создаёт отдельные тестовые учётные записи, не меняет существующие профили. 28 проверок пройдены: регистрация, дубли логина, вход, cookie, отзыв сессии, ограничение попыток, роли, чужие приглашения и сквозной контакт между независимыми работодателем и кандидатом. TypeScript — без ошибок.

У пользователей действительно отдельные кабинеты. Подтверждённые и опубликованные кандидаты доступны работодателям в общем каталоге; приватные данные скрыты. Приглашение хранится у работодателя и адресуется конкретному владельцу профиля. Только получатель может ответить.

## Запуск

После установки зависимостей и сборки примените только ещё не применённые миграции в порядке 0000, 0001. Для существующей локальной базы, где уже есть records:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_small_mordo.sql
npm run dev
```

Теперь главная страница содержит собственную форму входа. Локальная имитация личности Seedy больше не используется приложением. Нужно зарегистрировать аккаунт кандидата или работодателя.

Подтверждение email и восстановление пароля не реализованы: для них потребуется отправка писем. Старые демонстрационные записи сохранены, но автоматически к новым учётным записям не привязываются. Исторический скрипт check-workflow.py относится к версии 0.1; для текущей версии использовать check-auth.py.

Для доступа к опубликованной странице без внешнего входа ChatGPT требуется публичная настройка доступа сайта. Собственная авторизация кабинетов остаётся обязательной независимо от этой настройки.
