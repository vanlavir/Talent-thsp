## Сценарий для жюри

1. Создать аккаунт кандидата на собственной почте. Код запрашивается автоматически; ввести код из письма.
2. Заполнить профиль, отрасль, софт-скиллы, согласие и видимость; при желании образование и портфолио.
3. Открыть «Подтвердить навыки», выбрать уровень, пройти обязательный опрос, решить 15 задач. Категория присваивается только при успешном результате. Не использовать ключи ответов для заявления о качестве грейда.
4. В другом браузере либо отдельном профиле создать работодателя и подтвердить его почту. Заполнить компанию.
5. Найти категорию кандидата, проверить объяснение выдачи и скрытие контакта, отправить зарплатную вилку и дополнительное задание.
6. Кандидат открывает предложение, отправляет текст решения и при необходимости ссылку, принимает предложение.
7. Работодатель видит принятый статус, решение и открывшийся контакт. Скачивание PDF доступно кандидату из сохранённого профиля.

Тестовые предустановленные кандидаты не являются реальными участниками. API реестра ФСП не предоставлялся; модель интеграции описана в документации. Получение ID не означает проверку достижений.

## Воспроизводимые проверки

После установки зависимостей:

```sh
node --max-old-space-size=128 scripts/validate-priority.cjs
node scripts/check-mailru.cjs
node scripts/check-pilot.cjs
```

HTTP-проверка выполняется только на новой изолированной локальной базе с запущенным npm start:

```sh
node scripts/check-local-http.cjs http://127.0.0.1:8787 .wrangler/state
```

Она создаёт синтетические аккаунты и получает эталоны только из этой локальной базы. Скрипт запрещает внешний адрес.

Браузерная проверка — отдельный инструмент разработки scripts/check-browser.cjs, требует Playwright и локального Chromium/Edge, не входит в зависимости production-сайта. PLAYWRIGHT_PACKAGE_PATH указывает каталог установленного playwright, QA_BROWSER_PATH — браузер. Снимки и трассы сохраняются в выбранную локальную папку; трассы содержат данные тестовых сессий и не должны публиковаться вместе с реальными аккаунтами.
